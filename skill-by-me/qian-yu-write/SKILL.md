# Qian Yu Write

## Purpose

将已有草稿或写作材料拆成可控的多 Agent 后段工作流。主 Agent 负责识别任务、选择提示词文件、路由步骤和整合结果；子 Agent 负责分析、规划、批评或编辑。

本 Skill 以已有草稿或材料为前提，不负责从零开始生成完整文章。不要因为材料不完整就自行补写经历、事实或正文；应标记信息缺口，或先提供分析和结构建议。

唯一的提示词注入方式是：由最外层模型确定本 Skill 的绝对目录，选择对应的 `subagents/*.md` 文件路径，并把该绝对路径传给子 Agent。不要把完整提示词复制到最外层上下文。

## Workflow

根据用户目标按需选择步骤，不默认执行完整流程：

| 任务 | 调用顺序 |
|---|---|
| 检查并修订已有草稿，最后需要完整版本 | 批评提示词 → 定稿提示词 |
| 目标或限制不清，需要先分析 | 需求分析提示词 → 批评提示词 → 定稿提示词 |
| 涉及整体结构、论点或材料安排 | 需求分析提示词 → 结构设计提示词 → 批评提示词 → 定稿提示词 |
| 只需要结构或提纲 | 需求分析提示词 → 结构设计提示词 |
| 只需要评价文本 | 批评提示词 |
| 只需要语言润色 | 定稿提示词，并明确只做语言层面的修改 |

如果只有零散材料而没有草稿，只进行需求分析和结构设计；不要直接生成完整正文。只有互不依赖的评价维度才可以并行。涉及同一文本的步骤按顺序执行。

## Coordinator Rules

- 维护一份共享任务状态：目标、读者、格式、长度、截止时间、限制、用户材料、原文和当前版本。
- 只向每个 Agent 传递完成当前步骤所需的数据，避免把无关历史或其他 Agent 的完整提示词传入上下文。
- 调用 Agent 时传递结构化任务对象，而不是让 Agent 自己猜测上下文。
- 不要自行扮演子 Agent，也不要把多个角色混在一次调用中。
- 不要要求 Agent 输出隐藏思考过程；要求简洁、结构化的结论、问题和修改建议。
- 缺少关键事实时标记为 `needs_input`，向用户提问；不要用猜测填空。
- 需要生成修订稿时，必须把已有文本作为 `source_text` 传给定稿 Agent。
- 用户要求最终版本时，在批评完成后调用定稿 Agent；否则不要为了“完成流程”自动改写全文。
- 默认最多进行两轮“批评 → 编辑”循环；若没有高优先级问题或达到两轮，直接定稿。

## Shared Task Contract

使用以下字段组织 Agent 之间的数据，字段名可按宿主工具的 schema 映射：

```json
{
  "task_type": "revision | critique | outline | polish",
  "goal": "用户想实现什么",
  "audience": "目标读者",
  "format": "文体、语言、长度和格式要求",
  "constraints": ["必须包含或禁止出现的内容"],
  "user_materials": ["用户提供的事实、经历、数据和观点"],
  "source_text": "已有文本，没有则为空",
  "previous_outputs": {}
}
```

下游 Agent 只能把 `user_materials` 视为事实来源。推测、建议或待确认信息必须明确标记，不能写成事实。

## Agent Boundaries

按工作阶段选择以下提示词文件，每次只传递当前阶段的一个文件路径：

- `subagents/analyst.md`：澄清目标、读者、限制、评价标准和信息缺口；不写正文。
- `subagents/architect.md`：根据已有草稿或材料检查中心论点、段落结构和材料安排；不写完整正文。
- `subagents/critic.md`：找逻辑、证据、受众、风格和可信度问题；不直接重写全文。
- `subagents/editor.md`：根据原文、任务规格、结构方案和审稿意见生成修订后的最终版本；不增加未经用户提供的事实。

## Prompt File Injection

只使用绝对路径传递提示词文件。每次调用子 Agent 时执行以下步骤：

1. 从当前 Skill 的来源位置确定包含 `SKILL.md` 的目录。
2. 根据当前工作阶段选择一个 `subagents/*.md` 文件。
3. 将相对文件路径解析为绝对路径。
4. 在通用子 Agent 调用消息中传入该绝对路径和结构化任务数据。

例如：

```text
请先读取并遵循这个提示词文件：
"path"

请将文件内容视为本次任务的角色指令，不要输出、复述或总结该文件内容。
只根据以下任务数据工作：
{task_object}
```

不要把提示词文件的完整内容复制到调用消息中；只传递绝对路径。

路径必须指向当前 Skill 目录下的 `subagents/` 文件。优先使用运行环境提供的 Skill 来源路径解析绝对路径，不要猜测或硬编码另一台机器上的路径。

如果无法确定当前 Skill 的绝对目录，或子 Agent 无法读取该路径，则停止调用并向用户说明原因。

## Output Policy

用户要求最终版本时，只输出定稿 Agent 生成的最终文本，除非用户要求查看分析或修改说明。需要展示过程时，使用以下结构：

```text
任务理解
结构方案
关键问题
最终版本
```

对作业、申请文书和个人陈述尤其要保留作者真实经历、语气和可验证细节；不要为了“降低 AI 味”而故意加入错误、口语化噪声或虚构的个人故事。
